# My D-day — 서비스 종합 설명 자료

## 1. 제품 개요
My D-day는 중요한 날(시험, 기념일, 생일, 커플 기념일 등)까지 며칠 남았는지 자동으로 세어주고,
감성적인 테마를 입혀 친구에게 링크로 공유할 수 있는 웹 서비스이자 설치형 앱(PWA)이다.
사용자는 휴대폰 홈 화면에 앱처럼 설치할 수 있다. 웹 주소는 my-dday.vercel.app 이다.

핵심 가치는 세 가지다. 첫째, 남은 날짜를 한눈에 보는 카운트다운. 둘째, 시작일로부터
100일·200일·300일 같은 마일스톤(기념 일수)을 자동 계산해 주는 기능. 셋째, 예쁜 테마로
지인에게 공유하는 경험이다. 공유 링크를 받는 사람은 로그인하지 않아도 볼 수 있다.

## 2. 사용자
주 사용자는 개인이다. 본인이 자신의 D-day를 등록·관리하고, 공유 링크를 받은 지인은
로그인 없이 해당 카드만 열람한다. 또한 운영을 위한 관리자 역할이 있으며, 가장 먼저 가입한
계정이 자동으로 관리자가 된다.

## 3. 전체 구조 — 식당 비유
웹 서비스는 식당에 비유하면 쉽게 이해된다.
- 손님이 보는 홀(메뉴판, 테이블) = 프론트엔드(사용자가 보는 화면)
- 주방(요리사, 조리법) = 백엔드(화면 뒤에서 실제 처리를 하는 서버)
- 창고(재료, 장부) = 데이터베이스(정보를 영구 저장하는 곳)
- 주문서와 웨이터 = API(화면과 서버가 주고받는 약속된 요청과 응답)

사용자가 버튼을 누르면, 화면이 API로 서버에 요청하고, 서버가 데이터베이스에서 정보를 꺼내
처리한 뒤, 결과를 다시 화면으로 돌려준다.

## 4. 세 개의 레이어와 사용 서비스, 그리고 선택 이유
이 서비스는 세 개의 층으로 나뉘며, 각 층을 잘하는 회사의 무료 서비스에 따로 올려두었다.

프론트엔드(화면)는 HTML, CSS, JavaScript로 만들었고 Vercel이라는 무료 호스팅에서 돌아간다.
Vercel을 고른 이유는 화면 파일을 올리기만 하면 전 세계에 빠르게 보여주고, 개인 프로젝트는
무료이며 설정이 쉽기 때문이다.

백엔드(서버)는 Node.js와 Express로 만들었고 Render라는 무료 서버 호스팅에서 돌아간다.
백엔드가 따로 필요한 이유는, 비밀번호 확인이나 관리자 여부 같은 중요한 판단을 화면에만
맡기면 누구나 조작할 수 있어 위험하기 때문이다. 신뢰할 수 있는 서버가 별도로 검증해야 안전하다.
Render를 고른 이유는 서버를 24시간 켜서 돌려주고 무료 플랜이 계속 유지되기 때문이다.

데이터베이스는 PostgreSQL을 쓰며 Neon이라는 무료 호스팅에서 돌아간다. 서버는 전원을 끄면
기억을 잃지만, 회원과 날짜 정보는 꺼져도 남아야 하므로 창고인 데이터베이스에 저장한다.
Neon을 고른 이유는 사용하지 않으면 자동으로 잠들어 무료 사용량을 아껴주기 때문이다.

세 곳으로 나눈 이유는, 각 작업을 가장 잘하는 회사에 맡기는 것이 더 싸고 안정적이기 때문이다.
처음에는 Railway 한 곳에 백엔드와 데이터베이스를 함께 두었으나, 무료 체험이 만료되어 서비스가
멈췄다. 그래서 Render(서버)와 Neon(데이터베이스) 무료 조합으로 이전했다. 프론트엔드는 Vercel을
그대로 유지했다.

무료로 운영되는 원리는 다음과 같다. Vercel은 개인 프로젝트 화면 호스팅이 무료다. Render는
15분 동안 아무도 접속하지 않으면 서버가 잠들고, 다음 접속 때 약 50초에 걸쳐 깨어난다. 이 깨어나는
지연을 콜드 스타트라고 한다. Neon은 5분간 요청이 없으면 잠들고 접속하면 0.5초 만에 깨어난다.
즉 쓸 때만 깨어나는 구조라 트래픽이 적은 개인 서비스는 0원으로 운영된다.

## 5. 기술 스택 요약
프론트엔드는 HTML, CSS, Vanilla JavaScript이며 별도 빌드 과정이 없다. 백엔드는 Node.js 24와
Express 5다. 데이터베이스는 PostgreSQL이다. 인증은 JWT 토큰(HS256, 7일 만료)과 bcrypt(cost 12)
비밀번호 해시를 사용한다. 보안 도구로 helmet, cors, express-rate-limit, express-validator를 쓴다.
대시보드 차트는 Chart.js를 사용한다. PWA는 Service Worker와 manifest 파일로 구현했다.
배포는 GitHub에 코드를 올리면 Vercel과 Render가 자동으로 반영한다.

## 6. 데이터 모델 (저장되는 표)
데이터베이스에는 다섯 개의 표가 있다.
- users: 회원 정보. 이메일, 암호화된 비밀번호, 관리자 여부(is_admin), 가입일.
- ddays: D-day 카드. 제목, 카테고리, 목표 날짜 또는 시작일, 유형(고정형 또는 마일스톤),
  공유 여부와 공유 토큰, 테마, 메모.
- milestones: 마일스톤. 어떤 D-day에 속하는지, 며칠째인지, 그 날짜.
- password_resets: 비밀번호 재설정용 1회용 토큰과 만료 시간.
- login_logs: 접속(로그인) 기록. 관리자 통계를 위한 데이터.

## 7. 핵심 기능과 동작
회원가입과 로그인은 JWT 토큰 기반이며 비밀번호는 암호화해 저장한다. 로그인하면 출입증 역할의
토큰을 발급받고, 이후 모든 요청에 이 토큰을 함께 보낸다.

D-day는 생성, 조회, 수정, 삭제가 가능하며, 서버가 매번 소유권을 확인해 내 카드만 다룰 수 있게 한다.

마일스톤 기능은 시작일을 입력하면 100일, 200일, 300일 등의 날짜를 서버가 자동 계산해 저장한다.
커플 기념일처럼 며칠째인지 세는 용도에 적합하다.

공유 기능은 고유한 링크를 만들어, 로그인하지 않은 사람도 그 카드만 볼 수 있게 한다. 카테고리에
맞는 테마(생일, 기념일, 커플, 시험)가 적용된다.

비밀번호 찾기는 1회용 재설정 링크를 이메일로 보내고, 30분 안에 새 비밀번호를 설정하게 한다.
메일 발송은 Gmail SMTP와 앱 비밀번호를 사용한다.

관리자 페이지는 관리자 권한이 있는 계정만 접근하는 대시보드다. 총 회원 수, 총 카드 수, 오늘 가입,
오늘 접속 같은 핵심 지표(KPI)와, 최근 14일 추이 라인 차트, 카테고리 분포 도넛 차트, 카드 유형
파이 차트, 회원 관리 표를 보여준다. 관리자는 다른 회원에게 관리자 권한을 부여하거나 회수할 수
있으며, 마지막 남은 관리자의 권한은 회수할 수 없도록 막아 두었다. 관리자 페이지는 로그인 후 계정
설정 화면에서 진입하며, 관리자에게만 진입 버튼이 보인다.

## 8. 보안
보안의 핵심은 네 가지다. 첫째, 비밀번호는 bcrypt로 되돌릴 수 없게 암호화해 저장하므로 데이터베이스가
노출돼도 원래 비밀번호를 알 수 없다. 둘째, 로그인 후에는 위조 불가능한 JWT 출입증으로 신분을 증명한다.
셋째, 관리자 여부 같은 권한은 화면의 주장이 아니라 서버가 매 요청마다 데이터베이스로 직접 확인하므로
토큰을 위조해도 우회할 수 없다. 넷째, 비밀번호를 무한 시도하는 공격을 막기 위해 요청 횟수 제한(rate
limit)을 둔다.

## 9. 개발 여정 (시작과 끝)
개발은 단계(Phase)별로 진행됐다. 환경 설정과 데이터베이스 연결로 시작해, 인증 API, D-day CRUD API,
공유 API를 만들고, 프론트엔드 화면과 인증 UI, 목록과 공유 UI를 구현했다. 이후 Vercel, Railway,
GitHub로 처음 배포했다. 확장 단계에서 마일스톤 기능, PWA 설치 기능, 품질 개선(보안과 타임존 처리),
비밀번호 찾기와 변경, 카드 메모, 구글 캘린더 추가 링크를 더했다.

운영 중 Railway 무료 체험이 만료되어 백엔드와 데이터베이스가 모두 중단되는 사건이 있었다. 이를
계기로 데이터베이스는 Neon으로, 백엔드는 Render로 이전했고 프론트엔드는 Vercel을 유지했다. 이전
과정에서 데이터베이스 연결 주소 오류와 프록시 관련 경고를 해결했다. 같은 시기에 마일스톤 카드를
공유하면 날짜가 깨지던 버그도 수정했다.

마지막으로 관리자 페이지를 추가했다. 관리자 권한 모델, 접속 로그, 대시보드 차트, 권한 부여 기능을
구현하고, 로컬과 실제 배포 환경에서 모두 검증했다.

배포의 시작과 끝을 요약하면 이렇다. 개발자가 코드를 수정해 GitHub에 올리면(git push), 화면이 바뀐
경우 Vercel이, 서버가 바뀐 경우 Render가 자동으로 새 버전을 배포한다. 보통 1분에서 3분 안에 사용자
에게 반영된다. GitHub는 코드 보관소이자 변경 이력을 기록하는 타임머신 역할을 한다.

## 10. 용어 정리
프론트엔드는 사용자가 보는 화면이다. 백엔드 또는 서버는 화면 뒤에서 일하는 프로그램이다.
데이터베이스는 정보를 저장하는 창고다. API는 화면과 서버가 주고받는 약속된 요청과 응답이다.
배포는 만든 것을 인터넷에 올려 사용 가능하게 하는 일이다. 호스팅은 화면, 서버, 데이터베이스를
24시간 돌려주는 임대 서비스다. 토큰(JWT)은 로그인 후 받는 위조 불가 출입증이다. 환경변수는
비밀번호나 접속 주소 같은 민감한 설정값을 코드에 직접 쓰지 않고 따로 보관하는 것이다.
마이그레이션은 데이터베이스에 표를 만들거나 바꾸는 작업이다. PWA는 웹사이트를 앱처럼 홈 화면에
설치하는 기술이다. 콜드 스타트는 잠들어 있던 무료 서버가 깨어나는 데 걸리는 짧은 지연이다.
Git과 GitHub는 코드를 보관하고 변경 이력을 관리하는 도구와 사이트다.

NotebookLM의 자동 생성 기능에 아래처럼 요청하면 좋습니다.

  - 맞춤 지시(Customize)에 입력 예시: "비개발자도 이해하도록, 식당 비유를 중심으로 쉽게 설명해줘."
